# Certificate Generation Services

## Overview

This module provides cross-platform digital certificate generation compatible with:
- **Commercial Certificate Authorities** (DigiCert, Sectigo, GlobalSign, etc.)
- **Microsoft Certificate Services**
- **Adobe Sign** and **Adobe Acrobat** (PDF signing)
- **DocuSign**
- **Email clients** (Outlook, Gmail, Thunderbird via S/MIME)

## Cross-Platform Compatibility

### Certificate Format: PKCS#12 (.pfx/.p12)

All certificates are generated and exported in **PKCS#12** format, which is the universal standard supported by:

| Platform | Import Method | Certificate Store |
|----------|--------------|-------------------|
| **Windows** | Certificate Manager (certmgr.msc), `X509Store` API | Windows Certificate Store |
| **macOS** | Keychain Access, `security` command | Keychain |
| **Linux** | NSS tools, OpenSSL, system CA store | NSS database, `/etc/ssl/certs` |
| **1Password** | Import as "Document" or via CLI | Secure vault |

### X.509 Standard Compliance

Generated certificates follow **RFC 5280** (X.509 v3) with proper extensions:

#### Extended Key Usage (EKU) OIDs

| Usage | OID | Compatible With |
|-------|-----|-----------------|
| Email Signing (S/MIME) | `1.3.6.1.5.5.7.3.4` | Outlook, Gmail, Thunderbird, Apple Mail |
| Document Signing | `1.3.6.1.4.1.311.10.3.12` | Adobe Acrobat, Microsoft Word, DocuSign |
| Code Signing | `1.3.6.1.5.5.7.3.3` | Windows Authenticode, macOS codesign |

#### Key Specifications

- **Algorithm**: RSA
- **Key Size**: 2048-bit minimum (configurable up to 4096-bit)
- **Hash Algorithm**: SHA-256
- **Key Usage Flags**: DigitalSignature, KeyEncipherment
- **Validity Period**: Configurable (default 365 days)

### Subject Alternative Name (SAN)

Email addresses are included in the SAN extension (required for S/MIME by RFC 5322).

## Usage

### Automated Testing

Use `TestCertificateProvider` for automated tests:

```csharp
// Get cached test certificate (fast, for most tests)
var cert = TestCertificateProvider.GetEmailSigningCertificate();

// Generate fresh certificate (when you need unique certs)
var freshCert = TestCertificateProvider.GenerateFreshCertificate(
    "John Doe",
    "john@example.com",
    CertificateUsage.All);
```

### Production Use

```csharp
var generator = new CertificateGenerator();

// Self-signed certificate
var request = new CertificateRequest
{
    CommonName = "Jane Smith",
    Email = "jane@company.com",
    Organization = "Acme Corp",
    ValidityDays = 365,
    Usage = CertificateUsage.EmailSigning | CertificateUsage.DocumentSigning
};

var cert = generator.GenerateSelfSignedCertificate(request);

// Export for backup or import to 1Password
var pfxData = generator.ExportPfx(cert, "SecurePassword123!");
File.WriteAllBytes("jane-cert.pfx", pfxData);
```

### Test CA (Simulates Commercial CA)

```csharp
// Generate test CA
var ca = generator.GenerateTestCA("My Test CA");

// Issue certificate signed by test CA
var userCert = generator.GenerateTestCertificate(request, ca);

// This creates a proper certificate chain: userCert -> CA
```

## Switching from Test to Commercial Certificates

Test certificates generated by this service are **structurally identical** to commercial CA certificates. The only difference is the trust chain.

### To switch from test to production:

1. **Keep the same code** - APIs are identical
2. **Replace the certificate** - Use commercial CA cert instead of self-signed
3. **No format changes needed** - PKCS#12 format is universal
4. **Trust chain works automatically** - Commercial CAs are pre-trusted by OS

Example:

```csharp
// Testing
var testCert = generator.GenerateSelfSignedCertificate(request);

// Production - just load commercial cert instead
var productionCert = new X509Certificate2("commercial-cert.pfx", password);

// Same signing/encryption code works for both!
```

## Security Considerations

### For Testing (Insecure Storage Acceptable)

- Certificates stored in plain text test fixtures
- Hardcoded passwords acceptable
- No encryption at rest required
- Focus on automation speed

### For Production (Secure Storage Required)

- **Never** store private keys unencrypted
- Use OS certificate stores or password managers (1Password, etc.)
- Require strong passwords for PFX export
- Consider hardware security modules (HSM) for high-value keys

## Platform-Specific Installation

### Windows

```csharp
using var store = new X509Store(StoreName.My, StoreLocation.CurrentUser);
store.Open(OpenFlags.ReadWrite);
store.Add(cert);
store.Close();
```

Or via command line:
```powershell
certutil -user -p "password" -importpfx cert.pfx
```

### macOS

```bash
security import cert.pfx -k ~/Library/Keychains/login.keychain-db -P "password"
```

### Linux (NSS - used by Chrome, Firefox)

```bash
pk12util -i cert.pfx -d sql:$HOME/.pki/nssdb
```

### 1Password CLI

```bash
op document create cert.pfx --title "My Signing Certificate" --vault Personal
```
